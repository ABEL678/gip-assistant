## 3. Детали реализации

### 3.1. `_fetch_premise_ids` (TaskRepository)

```python
async def _fetch_premise_ids(self, task_id: UUID) -> list[UUID]:
    """Premise ID через цепочку: Task → Document → Premise.
    
    SELECT premise.id FROM premises
    JOIN documents ON premises.source_document_id = documents.id
    WHERE documents.rfi_id = :task_id
    """
    stmt = (
        select(PremiseModel.id)
        .join(DocumentModel, PremiseModel.source_document_id == DocumentModel.id)
        .where(DocumentModel.rfi_id == task_id)
    )
    result = await self._session.execute(stmt)
    return list(result.scalars().all())
```

**Важно:** для не-RFI Task этот метод не вызывается (проверка `is_rfi` в `_to_domain`). Но если вызван — вернёт `[]` (JOIN не найдёт строк, т.к. `documents.rfi_id` будет NULL).

### 3.2. RfiRepository — методы

| Метод | Реализация |
|-------|-----------|
| `list_rfis_by_project(project_id)` | `select(TaskModel).where(TaskModel.project_id == project_id, TaskModel.is_rfi == true)` |
| `get_rfi_by_id(id)` | `get_by_id(id)` + проверка is_rfi |
| `list_by_cause_decision(decision_id)` | `select(TaskModel).where(TaskModel.rfi_cause_decision_id == decision_id, TaskModel.is_rfi == true)` |
| `list_by_cause_goal(goal_id)` | `select(TaskModel).where(TaskModel.rfi_cause_goal_id == goal_id, TaskModel.is_rfi == true)` |
| `list_overdue(today: date, project_id: UUID) -> list[Task]` | `select(TaskModel).where(TaskModel.project_id == project_id, TaskModel.rfi_due_date < today, TaskModel.rfi_state.notin_([RfiState.CLOSED, RfiState.REGISTERED]))` |

**SqlAlchemyRfiRepository композирует SqlAlchemyTaskRepository (или переиспользует его `_to_domain`).** `premise_ids` — через `_fetch_premise_ids` (тот же, что в TaskRepository). Без дублирования `_to_domain`. |

### 3.3. RfiService — валидации

1. `project_id` существует (через ProjectRepository).
2. Ровно одна причина: `(rfi_cause_decision_id is not None) + (rfi_cause_goal_id is not None) == 1`.
3. `rfi_cause_decision_id` — из того же проекта (через DecisionRepository).
4. `rfi_cause_goal_id` — из того же проекта (через GoalRepository).
5. `rfi_state` — валидное значение RfiState.
6. `is_rfi = True` — выставляется сервисом, не из DTO.
7. `_fetch_premise_ids` — вызывается через TaskRepository (реализация в SqlAlchemyTaskRepository), не через RfiRepository.
8. Task.state при создании — NOT_STARTED (дефолт, в TaskStatus нет PLAN).

### 3.5. RfiProposal DTO

```python
class RfiProposal(BaseModel):
    id: UUID
    action: Literal["create", "escalate"]
    rule: str  # "decision_без_ид" | "rfi_просрочен"
    formulation: str
    rationale: str | None = None
    reason_decision_id: UUID | None = None
    existing_rfi_id: UUID | None = None
    rfi_due_date: date | None = None
    
    @model_validator(mode="after")
    def _check_action_fields(self):
        if self.action == "create" and self.existing_rfi_id is not None:
            raise ValueError("existing_rfi_id only for escalate")
        if self.action == "escalate" and self.existing_rfi_id is None:
            raise ValueError("existing_rfi_id required for escalate")
        return self
```
