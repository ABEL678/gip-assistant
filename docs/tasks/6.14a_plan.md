**Критерии готовности (DoD):**

2. `LLMProvider` (`qwen`, `openai_compatible`) и `DataSecurityLevel`

6. В `projects` есть `data_security_level` NOT NULL DEFAULT `green`;
   существующие строки получают `green`.
7. Не более одного активного провайдера гарантировано partial unique
   index `idx_llm_settings_active` (ноль активных допустим).
8. `LLMSettingsService` умеет: создать, обновить, активировать,
   деактивировать, удалить, отдать активного, расшифровать ключ
   для адаптера (6.14b).
9. `Project` (домен, модель, репозиторий, DTO, `create_project`)

10. Тесты: +30 (итого 480), `pytest` зелёный, `ruff check` чистый.
11. `alembic upgrade head` и `alembic downgrade -1` проходят без ошибок.

## 3. Архитектурные решения

### 3.1. Чистота домена

`domain/entities/llm_settings.py` и порты не импортируют
FastAPI/SQLAlchemy/Pydantic. Шифрование — через порт
`SecretCipherPort`; домен хранит **только ciphertext** и `last4`.

### 3.2. `LLMProvider` — enum, а не произвольная строка

`AGENTS.md` требует для enum-полей SQLAlchemy `Enum(..., create_type=False)`,
а не `String`. Поэтому:

- домен: `class LLMProvider(StrEnum): QWEN = "qwen"; OPENAI_COMPATIBLE = "openai_compatible"`;
- БД: PG enum-тип `llm_provider`, в модели
  `Enum(LLMProvider, name="llm_provider", create_type=False,
  values_callable=lambda e: [x.value for x in e])`.

`values_callable` обязателен: без него SQLAlchemy может записать имя
члена (`'QWEN'`) вместо значения (`'qwen'`) — особенно если исполнитель
передаст член enum, а не `.value`.

`DATABASE.md §2.21` сейчас описывает `provider` как `str(50)` — это
**документационное расхождение**, которое правится в этом же коммите
(см. §12). Альтернатива — оставить `String(50)` — отклонена: противоречит
`AGENTS.md` и допускает мусор в БД.

### 3.3. `DataSecurityLevel` — enum

- домен: `GREEN = "green"`, `YELLOW = "yellow"`, `RED = "red"`;
- БД: PG enum-тип `data_security_level`, в модели
  `Enum(DataSecurityLevel, name="data_security_level", create_type=False,
  values_callable=lambda e: [x.value for x in e])`.

`DATABASE.md §2.1` сейчас описывает `VARCHAR(10)` — правится на enum.
Светофор проверяется в 6.14b по значению enum, **не** regex по тексту.

### 3.4. Шифрование — порт + Fernet-адаптер

- Порт `domain/ports/secret_cipher.py`: `encrypt`, `decrypt`,
  `is_configured`.
- Адаптер `adapters/security/fernet_cipher.py`: Fernet,
  ключ `LLM_ENCRYPTION_KEY` из настроек.
- В БД — `api_key_encrypted: bytes` (Fernet-токен) и
  `api_key_last4: str | None` (не секрет, для UI).
- Plaintext живёт только в памяти: в сервисе при create/update и в
  `RuntimeLLMAdapter` (6.14b) при вызове.
- Ключ и plaintext **никогда** не логируются.

### 3.5. `LLMProviderPort` — только контракт

В 6.14a объявляется ABC, реализаций нет. Сигнатура:

```python
class LLMProviderPort(ABC):
    @abstractmethod
    async def generate(
        self,
        prompt: str,
        system_prompt: str | None = None,
        *,
        project_id: UUID,
    ) -> str: ...

    @abstractmethod
    async def health_check(self) -> bool: ...
```

`project_id` — keyword-only и обязательный: светофор нельзя забыть
(случайный вызов без проекта должен падать на уровне сигнатуры).
`RuntimeLLMAdapter`, `QwenAdapter`, `OpenAICompatibleAdapter` — 6.14b.

### 3.6. `params` — JSONB

`params: dict[str, Any]`, колонка `JSONB NOT NULL DEFAULT '{}'::jsonb`.
GIN-индекс не нужен: по параметрам не ищем. Валидируются только
известные ключи (`temperature`, `max_tokens`), остальные сохраняются
как есть — расширение под провайдера без миграции.

### 3.7. Не более одного активного провайдера

Partial unique index гарантирует `≤ 1`; ноль активных допустим
(см. §3.8).

```sql
CREATE UNIQUE INDEX idx_llm_settings_active
ON llm_settings (is_active)
WHERE is_active = true;
```

Сервис при активации сначала делает `deactivate_all()` (с `flush`),
затем сохраняет целевую строку активной. Это исключает нарушение
уникальности при переключении.

### 3.8. Seed-строки нет

Миграция не создаёт дефолтную настройку. Пока активной строки нет,
`get_active()` возвращает `None`; `GET status` в 6.14c покажет
«не настроено». Автосоздание провайдера — не задача слоя данных.

## 5. Домен

### 5.1. `LLMSettings`

```python
@dataclass
class LLMSettings:
    provider: LLMProvider
    model_name: str
    base_url: str | None = None
    api_key_encrypted: bytes | None = None
    api_key_last4: str | None = None
    params: dict[str, Any] = field(default_factory=dict)
    is_active: bool = False
    id: UUID = field(default_factory=uuid4)
    created_at: datetime | None = None
    updated_at: datetime | None = None
```

Поля `api_key` (plaintext) в домене **нет** — только ciphertext.
Дефолт `params` — пустой dict; значения по умолчанию для
`temperature` / `max_tokens` подставит адаптер в 6.14b.

### 5.2. `Project`

Добавляется:

```python
data_security_level: DataSecurityLevel = DataSecurityLevel.GREEN
```

### 5.3. Порты

`LLMSettingsRepository` (в `domain/ports/repositories.py`, рядом с
остальными репозиториями):

```python
class LLMSettingsRepository(ABC):
    async def get_by_id(self, settings_id: UUID) -> LLMSettings | None: ...
    async def get_active(self) -> LLMSettings | None: ...
    async def list_all(self) -> list[LLMSettings]: ...
    async def save(self, settings: LLMSettings) -> LLMSettings: ...
    async def delete(self, settings_id: UUID) -> None: ...
    async def deactivate_all(self) -> None: ...
```

`deactivate_all()` обязателен: без него `activate()` нарушит
partial unique index. Метод делает `UPDATE ... SET is_active = false
WHERE is_active = true` и `flush()`.

`SecretCipherPort`:

```python
class SecretCipherPort(ABC):
    @abstractmethod
    def is_configured(self) -> bool: ...
    @abstractmethod
    def encrypt(self, plaintext: str) -> bytes: ...
    @abstractmethod
    def decrypt(self, token: bytes) -> str: ...
```

## 6. Модель БД и миграция

### 6.1. Таблица `llm_settings`

| Поле | Тип | Ограничения |
|---|---|---|
| id | UUID | PK, default — `uuid4()` в приложении |
| provider | `llm_provider` | NOT NULL |
| model_name | VARCHAR(100) | NOT NULL |
| base_url | VARCHAR(500) | nullable |
| api_key_encrypted | BYTEA | nullable, Fernet-ciphertext |
| api_key_last4 | VARCHAR(4) | nullable, не секрет |
| params | JSONB | NOT NULL, server_default `'{}'::jsonb` |
| is_active | BOOLEAN | NOT NULL, server_default `false` |
| created_at | TIMESTAMPTZ | NOT NULL, server_default `now()` |
| updated_at | TIMESTAMPTZ | NOT NULL, `TimestampMixin`: server_default `now()` + `onupdate=func.now()` |

**CHECK:**

- `ck_llm_settings_key_pair`:
  `(api_key_encrypted IS NULL) = (api_key_last4 IS NULL)` —
  ключ и last4 хранятся только вместе (нет половинчатого состояния).

**Индексы:**

- `llm_settings_pkey` (PK);
- `idx_llm_settings_active` — UNIQUE, partial
  `WHERE is_active = true`.

**Обязательное объявление в модели** (`LLMSettingsModel.__table_args__`):

```python
__table_args__ = (
    CheckConstraint(
        "(api_key_encrypted IS NULL) = (api_key_last4 IS NULL)",
        name="ck_llm_settings_key_pair",
    ),
    Index(
        "idx_llm_settings_active",
        "is_active",
        unique=True,
        postgresql_where=text("is_active = true"),
    ),
)
```

`provider` объявляется как `Enum(LLMProvider, name="llm_provider",
create_type=False, values_callable=lambda e: [x.value for x in e])`.
Без `__table_args__` `alembic check` увидит `remove_index` (индекса нет
в metadata); без `values_callable` enum может записаться именем члена
вместо значения.

**FK:** нет. Настройки глобальные, не привязаны к проекту
(светофор — свойство проекта, настройки провайдера — общие).

### 6.2. `projects.data_security_level`

- Тип: enum `data_security_level`.
- `NOT NULL`, `server_default=text("'green'")`.
- Существующие строки при миграции получают `green`.
- Индекс не нужен: поле читается точечно по PK проекта.

### 6.3. Миграция

- Базовая ревизия: `b76037d5f79c` (текущий head).
- Файл создаётся **вручную**: `alembic revision -m "add llm_settings
  and data_security_level"` (без `--autogenerate`).
- Причина: `alembic autogenerate` тянет известный pre-existing дрейф
  (`project_standards.value`, `result_goals.created_at`,
  `standard_goals.created_at`). Рукописная миграция его не касается.

**upgrade():**

1. Идемпотентно создать `llm_provider`:
   `DO $$ BEGIN CREATE TYPE llm_provider AS ENUM ('qwen',
   'openai_compatible'); EXCEPTION WHEN duplicate_object THEN NULL;
   END $$;`
2. То же для `data_security_level` (`green`, `yellow`, `red`).
3. `ALTER TABLE projects ADD COLUMN data_security_level
   data_security_level NOT NULL DEFAULT 'green';`
4. `CREATE TABLE llm_settings (...)` — колонки из §6.1,
   `provider` через `sa.Enum(..., create_type=False)`.
   CHECK и partial unique index — в `op.create_check_constraint`
   / `op.create_index` и одновременно в `__table_args__` модели (§6.1).
5. `CREATE UNIQUE INDEX idx_llm_settings_active ... WHERE is_active = true;`
6. `CHECK ck_llm_settings_key_pair`.

**downgrade():**

1. `DROP INDEX idx_llm_settings_active;`
2. `DROP TABLE llm_settings;`
3. `ALTER TABLE projects DROP COLUMN data_security_level;`
4. `DROP TYPE IF EXISTS data_security_level;`
5. `DROP TYPE IF EXISTS llm_provider;`

**Проверка после миграции:**

- `alembic upgrade head` — без ошибок;
- `alembic downgrade -1` → `alembic upgrade head` — обратимость;
- `alembic check` до миграции (baseline) и после: список расхождений
  не должен пополниться. Допустимы только 3 известных pre-existing
  дрейфа из `TASKS.md §4`; команда при них завершается ненулевым
  кодом, поэтому сравниваются списки, а не код возврата.

## 7. Репозиторий

`backend/src/adapters/db/repositories/llm_settings_repository.py`

```python
class SqlAlchemyLLMSettingsRepository(LLMSettingsRepository):
    def __init__(self, session: AsyncSession) -> None: ...
```

Методы:

| Метод | Реализация |
|---|---|
| `get_by_id` | `session.get(LLMSettingsModel, id)` → `_to_domain` |
| `get_active` | `SELECT ... WHERE is_active IS TRUE LIMIT 1` |
| `list_all` | `ORDER BY created_at DESC` |
| `save` | `session.merge` → `flush` → `refresh` → повторное чтение |
| `delete` | `DELETE WHERE id = ...` + `flush` |
| `deactivate_all` | `UPDATE ... SET is_active = false WHERE is_active = true` + `flush` |

Маппинг:

- `_to_domain`: `LLMProvider(model.provider)`,
  `dict(model.params or {})`, `api_key_encrypted=model.api_key_encrypted`;
- `_to_model`: `provider=domain.provider.value`,
  `params=domain.params`; **`created_at`/`updated_at` не передаются** —
  их заполняет `TimestampMixin` / server_default (как в
  `project_repo.py` и `goal_repository.py`). Передача `None` из домена
  вставила бы NULL в NOT NULL-колонки.

`session.commit()` не вызывается — коммит в `get_db_session`
(`AGENTS.md`).

Экспорт: `adapters/db/repositories/__init__.py` и
`adapters/db/models/__init__.py`.

## 8. Сервис

`backend/src/domain/services/llm_settings_service.py`

```python
class LLMSettingsService:
    def __init__(
        self,
        repo: LLMSettingsRepository,
        cipher: SecretCipherPort,
    ) -> None: ...
```

### 8.1. Методы

| Метод | Поведение |
|---|---|
| `list_all()` | все настройки |
| `get(id)` | `None`, если нет |
| `get_active()` | активная или `None` |
| `create(provider, model_name, *, base_url=None, api_key=None, params=None, is_active=False)` | создаёт; `api_key=""` эквивалентен `None` (ключа нет); при `is_active=True` сначала `deactivate_all()` |
| `update(id, *, provider=None, model_name=None, base_url=None, api_key=None, params=None)` | частичное обновление |
| `activate(id)` | `deactivate_all()` → `is_active=True` → `save` |
| `deactivate(id)` | `is_active=False` → `save` |
| `delete(id)` | удаляет; нет строки → `ValueError` |
| `get_api_key(id)` | расшифровывает ключ для адаптера; нет строки → `ValueError`; ключа нет → `None` |

### 8.2. Семантика sentinel-полей

| Значение | Смысл |
|---|---|
| `None` | не менять |
| `""` (пустая строка) | очистить (`base_url` → `NULL`; `api_key` → `NULL`/`NULL`) |
| непустая строка | заменить |
| `params={}` (в `update`) | заменить на пустой dict (не «не менять») |

В `create` пустая строка `api_key` трактуется как «ключа нет»
(эквивалент `None`), а не как ошибка длины. Это совпадает со стилем
`RfiUpdate` (`None` = «не менять»).

### 8.3. Валидации (ValueError)

1. `model_name`: `strip()`, непустое, ≤ 100.
2. `base_url`: `strip()`; если непустое — только `http://` / `https://`,
   ≤ 500.
3. `api_key` (при создании/замене): `strip()`, длина ≥ 4, ≤ 1000;
   `api_key_last4 = api_key[-4:]`.
4. `params`: dict; `temperature` (если есть) — число 0..2;
   `max_tokens` (если есть) — int > 0. Неизвестные ключи сохраняются.
5. `provider`: типизирован `LLMProvider`; Pydantic-валидация — 6.14c.
6. `activate`/`deactivate`/`delete`/`get_api_key`: нет строки → `ValueError`.
7. При `encrypt`/`decrypt` без `LLM_ENCRYPTION_KEY` → `ValueError`
   (текст без секрета).

Логирование — только идентификаторы и факт операции
(`llm_settings_created`, `llm_settings_activated`, …). Ключ,
ciphertext и plaintext в лог не попадают.

## 10. Шифрование

### 10.1. Настройки

В `config/settings.py`:

```python
LLM_ENCRYPTION_KEY: str = ""
```

Пустой дефолт — чтобы приложение и текущие тесты не падали без ключа.
Ошибка возникает только при попытке шифрования/расшифровки.

`.env.example` — добавить:

```
# Fernet-ключ для llm_settings.api_key_encrypted
# Генерация: python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
LLM_ENCRYPTION_KEY=
```

`.env` не трогаем.

### 10.2. `FernetCipher`

- `__init__(key: str)`: пустой ключ → `is_configured() = False`;
  непустой невалидный → `ValueError` (Fernet сам проверит).
- `encrypt`: `Fernet(key).encrypt(plaintext.encode()).decode?` —
  **нет**: возвращаем `bytes` (как в БД).
- `decrypt`: `Fernet(key).decrypt(token).decode()`.
- Без ключа `encrypt`/`decrypt` → `ValueError("LLM_ENCRYPTION_KEY не задан")`.
- Каждый вызов создаёт `Fernet` из ключа (дёшево) либо кэширует
  экземпляр в `__init__`. Выбираем кэш в `__init__` при валидном ключе.

### 10.3. Зависимость

Решение координатора: `cryptography>=43` добавляется в
`backend/pyproject.toml` явно (секция `[project].dependencies`).
Транзитивная установка через `python-jose[cryptography]` больше не
единственная опора. Версия в окружении (50.0.2) требованию `>=43`
соответствует. См. §13 (R2) — риск закрыт.

## 13. Риски и открытые вопросы

**R1. `spec_week_4.md` не содержит 6.14. — ЗАКРЫТ.**
Решение координатора: опираемся на `TASKS.md §3` и
`MASTER_SPEC.md §4.2`. `spec_week_4.md` не меняем.

**R2. `cryptography` — ЗАКРЫТ.**
Решение координатора: `cryptography>=43` добавляется в
`backend/pyproject.toml` явно. Транзитивная установка через
`python-jose[cryptography]` больше не единственная опора.

**R3. Типы в `DATABASE.md` расходятся с `AGENTS.md`. — РЕШЕНО.**
Решение координатора: `provider` — PG enum. `DATABASE.md §2.1` и
§2.21 приводятся к enum в этом же коммите.

**R4. Нет роута изменения `Project.data_security_level`. — РЕШЕНО.**
`PATCH /api/projects/{id}` в 6.14a не добавляется. Поле задаётся при
создании через `create_project` (простая передача поля, не новый
роут) и читается через `ProjectRead`. Изменение после создания —
6.14c/d; `ProjectUpdate` остаётся мёртвым DTO и проверяется только
схемой.

**R5. Нет активной настройки после миграции.**
`get_active()` → `None`, пока админка (6.14c) не создаст строку.
Для демо 6.14b это означает «LLM не настроена» — корректное состояние.

**R6. Посторонние whitespace-изменения. — РЕШЕНО.**
Решение координатора: игнорировать, в коммит 6.14a не включать.

**R7. `Project.stage` в репозитории не конвертируется в enum.**
Существующее поведение (`_to_domain` кладёт строку). Для нового поля
конвертация делается явно. Старое поведение не трогаем — вне задачи.

**R8. `api_key_encrypted` — BYTEA.**
Fernet возвращает `bytes`; asyncpg маппит `LargeBinary` в BYTEA.
Строковое хранение отклонено: `DATABASE.md §2.21` фиксирует `bytes`.

**R9. Порядок `deactivate_all()` → `save()` внутри одной транзакции.**
Без `flush()` между операциями unique index может сработать на старом
значении. В репозитории `deactivate_all()` делает `flush()`; тест
№2 из §11.4 проверяет и переключение, и ограничение на реальной БД.
