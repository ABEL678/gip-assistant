## 1. Цель и критерии готовности

**Цель:** дать работе с LLM переключаемый слой адаптеров:
локальный `QwenAdapter`, облачный `OpenAICompatibleAdapter` и диспетчер
`RuntimeLLMAdapter` с TTL-кэшем 60 секунд и светофором по
`Project.data_security_level`.

**Критерии готовности (DoD):**

1. `OpenAICompatibleAdapter` реализует `LLMProviderPort`:
   `generate()` через `POST {base_url}/chat/completions`,
   `health_check()` через `GET {base_url}/models`.
2. `QwenAdapter` — наследник `OpenAICompatibleAdapter` с локальными
   дефолтами (`base_url`, необязательный ключ).
3. `RuntimeLLMAdapter` реализует `LLMProviderPort`:
   - получает данные через async-загрузчики (без хранения сессии);
   - расшифровывает ключ только в памяти;
   - кэширует готовый адаптер 60 секунд (`time.monotonic`);
   - имеет `invalidate()` для мгновенного сброса после смены провайдера;
   - перед генерацией проверяет светофор проекта.
4. `RED` + облачный провайдер → `ValueError` **до** расшифровки ключа
   и до сетевого вызова; `RED` + локальная Qwen разрешён (`RULES.md §12.5.6`).
5. Нет активной настройки → `LLMProviderError`; `health_check()` → `False`.
6. Ошибки сети/HTTP/разбора ответа, а также ошибки загрузки настроек/ключа
   → `LLMProviderError`.
7. В логи не попадают prompt, api_key, ciphertext, тело ответа.
8. Новых зависимостей нет: используется уже объявленный `httpx>=0.28`.
9. Тесты: ≥36; `pytest` зелёный; `ruff check` по затронутым файлам чистый.
10. Миграций, роутов, DI и UI в 6.14b нет; в DI/пайплайн попадает
    только `RuntimeLLMAdapter`.

## 3. Архитектурные решения

### 3.1. Оба провайдера — OpenAI-compatible HTTP

`OpenAICompatibleAdapter` — базовый HTTP-адаптер:

- `POST {base_url}/chat/completions` — генерация;
- `GET {base_url}/models` — health check;
- заголовок `Authorization: Bearer <api_key>`, если ключ есть;
- таймаут: connect 5s, read 60s (настраивается конструктором).

`QwenAdapter` наследует его и задаёт локальные дефолты:
`base_url="http://localhost:8000/v1"`, `model_name="Qwen/Qwen2.5-7B-Instruct"`,
ключ необязателен. Это совместимо с vLLM и Ollama (`/v1`).
Нативный Qwen API (не OpenAI-совместимый) **не поддерживаем** в MVP —
при необходимости задаётся другой `base_url`.

Альтернатива (отдельная реализация Qwen под Ollama `/api/generate`)
отклонена: дублирует HTTP-код ради одного эндпоинта.

### 3.2. Домен остаётся чистым

`LLMProviderError` объявляется в `domain/ports/llm_provider.py`
(наследник `RuntimeError`). Это доменное исключение без импортов
`httpx`. Адаптеры оборачивают сетевые ошибки в него.

В порт добавляется неабстрактный `async def aclose(self) -> None`,
чтобы диспетчер мог освобождать HTTP-клиенты. Реализации по умолчанию
ничего не делают.

### 3.3. `RuntimeLLMAdapter` — диспетчер, не провайдер

**Жизненный цикл (решение по блокеру аудита).** Runtime — singleton
приложения, но **не держит** `AsyncSession`, `LLMSettingsService` или
`ProjectRepository` request-scope. Вместо этого он принимает async-загрузчики:

```python
RuntimeLLMAdapter(
    load_active_settings: Callable[[], Awaitable[LLMSettings | None]],
    load_api_key: Callable[[UUID], Awaitable[str | None]],
    load_project: Callable[[UUID], Awaitable[Project | None]],
    *,
    ttl_seconds: float = 60.0,
    clock: Callable[[], float] = time.monotonic,
    adapter_factory: Callable[[LLMSettings, str | None], LLMProviderPort] | None = None,
)
```

- `load_active_settings()` — активная настройка **без** ключа.
- `load_api_key(settings_id)` — расшифрованный ключ; вызывается только
  при построении/обновлении адаптера.
- `load_project(project_id)` — проект для светофора.
- `ttl_seconds` / `clock` — детерминированные тесты TTL.
- `adapter_factory` — тестовая подмена фабрики; по умолчанию `_build_adapter`.

В 6.14c DI собирает загрузчики как замыкания: каждое обращение открывает
свежую `AsyncSessionLocal()` и закрывает её после запроса. Runtime
кэширует только готовый адаптер (HTTP-клиент), не сессию.
Это снимает конфликт «singleton + закрытая сессия» и сохраняет TTL.

Диспетчер **не** создаёт `AsyncSession`, не читает модели напрямую,
не хранит plaintext отдельно от вложенного адаптера.

### 3.4. Светофор

Перед `generate()`:

1. `project = await load_project(project_id)`;
2. `project is None` → `ValueError("Проект ... не найден")`;
3. `settings = await load_active_settings()`;
4. `settings is None` → `LLMProviderError("LLM не настроена")`;
5. если `project.data_security_level is DataSecurityLevel.RED`
   **и** `settings.provider is LLMProvider.OPENAI_COMPATIBLE` →
   `ValueError("LLM запрещён: проект в красной зоне ...")`;
6. `GREEN` / `YELLOW` — вызов разрешён для любого провайдера;
7. `RED` + `QWEN` — локальная модель разрешена (`RULES.md §12.5.6`:
   ограничение сформулировано для облачного вызова).

Проверка `RED` для облака выполняется **до** `load_api_key()`: ключ
не расшифровывается. Метаданные настройки читаются до проверки, потому
что от провайдера зависит политика.

`YELLOW` не блокируется: обезличивание — ответственность пользователя
(`AGENTS.md`, периметр данных). Изменение политики — только через
`RULES.md` и согласование управляющего.

### 3.5. TTL-кэш 60 секунд

Состояние диспетчера:

- `_adapter: LLMProviderPort | None`;
- `_cache_key: tuple[UUID, datetime | None] | None` — `(settings.id, settings.updated_at)`;
- `_cached_at: float = float("-inf")`;
- `_in_flight: int = 0`;
- `_retired: list[LLMProviderPort] = []`;
- `_lock: asyncio.Lock`.

Алгоритм `generate()`:

1. Светофор (§3.4), затем `settings = await load_active_settings()`.
2. Под `_lock`:
   - `key = (settings.id, settings.updated_at)`;
   - если `_adapter is not None`, `key == _cache_key`,
     `clock() - _cached_at < ttl_seconds` — взять из кэша;
   - иначе `api_key = await load_api_key(settings.id)`,
     `new_adapter = adapter_factory(settings, api_key)`;
     старый адаптер → `_retired`, новый → `_adapter`,
     `_cache_key = key`, `_cached_at = clock()`;
   - `_in_flight += 1`.
3. Вызвать `_adapter.generate(...)` **вне** `_lock`.
4. В `finally`: под `_lock` `_in_flight -= 1`; если `_in_flight == 0` —
   закрыть все `_retired` (`await adapter.aclose()`), очистить список.

`invalidate()` (6.14c: `switch`, `update`, `deactivate`, `delete`):

- под `_lock` перенести `_adapter` в `_retired`, обнулить кэш;
- если `_in_flight == 0` — сразу закрыть `_retired`.

`aclose()` диспетчера = `invalidate()`; отложенные адаптеры закроются
после завершения in-flight вызовов. Так `invalidate()` не закрывает
HTTP-клиент под работающим `generate()`.

**Почему метаданные читаются каждый вызов:** `id`/`updated_at` меняются
при `switch/update/deactivate/delete`, поэтому смена провайдера и ключа
видна сразу, без ожидания TTL. TTL 60s кэширует **клиент** для той же
версии настройки и ограничивает пересоздание адаптеров.

**Почему TTL, а не событие из БД:** `RULES.md §12.5.6` фиксирует TTL 60s
и смену без перезапуска; 6.14c дополнительно вызывает `invalidate()`.

### 3.6. Выбор адаптера

```python
LLMProvider.QWEN             → QwenAdapter(...)
LLMProvider.OPENAI_COMPATIBLE → OpenAICompatibleAdapter(...)
```

- `model_name` — из `settings.model_name`;
- `base_url`:
  - Qwen: `settings.base_url or QwenAdapter.DEFAULT_BASE_URL`;
  - OpenAI-compatible: `settings.base_url`; `None` → `LLMProviderError`;
- `api_key` — расшифрованный или `None`;
- `params` — **копия** `settings.params`; `None`-значения отбрасываются;
  дефолты (`temperature=0.2`, `max_tokens=1024`) применяются только
  к отсутствующим ключам.

Неизвестный провайдер (на будущее) → `LLMProviderError`.

### 3.7. Ошибки и health check

- Сеть, таймаут, non-2xx, невалидный JSON, пустой `choices[0].message.content`
  → `LLMProviderError` с провайдером/статусом, **без тела ответа**.
- В `RuntimeLLMAdapter.generate()` ошибки `load_active_settings` /
  `load_api_key` / `_build_adapter` оборачиваются в `LLMProviderError`
  (кроме `ValueError` светофора/отсутствия проекта — они пробрасываются).
- `health_check()` никогда не бросает: ловит `Exception`
  (не `BaseException`/`CancelledError`) → `False`.
- `RuntimeLLMAdapter.health_check()`:
  - нет активной настройки → `False`;
  - ошибка построения/расшифровки/сети → `False`;
  - иначе результат вложенного адаптера.
- `RED` в `health_check()` не проверяется: у health check нет проекта.
- Health-таймаут — отдельный, 5 секунд; основной клиент — read 60s.
- Если `GET /models` вернул 404/405 (шлюз не поддерживает), health
  выполняет минимальный `POST /chat/completions` (`max_tokens=1`,
  `temperature=0`) и считает `True` при 2xx.

### 3.8. Логирование

Только метаданные:

```text
llm_request provider=qwen model=... project_id=...
llm_response provider=... duration_ms=...
llm_error provider=... status=...
```

Запрещено логировать: `prompt`, `system_prompt`, `api_key`,
`api_key_encrypted`, тело ответа, заголовки Authorization.

## 5. Контракты

### 5.1. `LLMProviderPort` (дополнение)

```python
class LLMProviderError(RuntimeError):
    """Ошибка LLM-провайдера (сеть/HTTP/формат ответа)."""


class LLMProviderPort(ABC):
    @abstractmethod
    async def generate(...) -> str: ...

    @abstractmethod
    async def health_check(self) -> bool: ...

    async def aclose(self) -> None:
        """Освободить ресурсы. По умолчанию — no-op."""
        return None
```

### 5.2. `OpenAICompatibleAdapter`

```python
class OpenAICompatibleAdapter(LLMProviderPort):
    def __init__(
        self,
        *,
        model_name: str,
        base_url: str,
        api_key: str | None = None,
        params: dict[str, Any] | None = None,
        client: httpx.AsyncClient | None = None,
        timeout: float = 60.0,
        connect_timeout: float = 5.0,
        health_timeout: float = 5.0,
    ) -> None: ...

    async def generate(self, prompt, system_prompt=None, *, project_id) -> str: ...
    async def health_check(self) -> bool: ...
    async def aclose(self) -> None: ...
```

Правила:

- `base_url` обязателен, `http(s)://`, trailing `/` срезается;
- `client` можно передать для тестов (`httpx.MockTransport`);
- если клиент создан адаптером — `aclose()` его закрывает;
- таймаут клиента: `httpx.Timeout(timeout, connect=connect_timeout)`;
- health-запрос — отдельный `health_timeout=5.0`;
- `params` копируется; `None`-значения отбрасываются;
  `temperature` по умолчанию `0.2`, `max_tokens` — `1024`;
- сообщения: `[{"role": "system", ...}]` (если есть) + `[{"role": "user", ...}]`;
- ответ: `choices[0].message.content` (строка, непустая);
- health: `GET /models`; при 404/405 — минимальный
  `POST /chat/completions` (`max_tokens=1`, `temperature=0`).

## 8. Риски и открытые вопросы

**R1. Формат локальной Qwen.**
План предполагает OpenAI-compatible `/v1` (vLLM/Ollama). Если на VPS
будет нативный API Qwen — потребуется отдельный адаптер. Требует
подтверждения при деплое.

**R2. `RED` и локальная Qwen.**
План следует букве `RULES.md §12.5.6`: блокируется только облачный
провайдер (`OPENAI_COMPATIBLE`). `RED` + `QWEN` разрешён. Если политика
должна стать строже (блокировать и локальную модель) — это изменение
`RULES.md` и решение управляющего, не самовольная правка кода.

**R3. Дефолтный `base_url` Qwen.**
`http://localhost:8000/v1` — типовой vLLM. Если Ollama — в настройках
указывается `http://localhost:11434/v1`. Хардкод только как fallback;
фабрика обязана использовать `settings.base_url or DEFAULT_BASE_URL`.

**R4. TTL 60s и смена провайдера.**
Метаданные активной настройки читаются на каждый `generate()`, а ключ
кэша — `(id, updated_at)`, поэтому `switch/update/deactivate/delete`
видны сразу. TTL 60s ограничивает пересоздание HTTP-клиента для той же
версии настройки. `invalidate()` в 6.14c — дополнительная страховка.

**R5. `YELLOW` не блокируется.**
Обезличивание — ответственность пользователя (`AGENTS.md`). Если нужна
жёсткая проверка — отдельное решение.

**R6. `health_check()` без активной настройки.**
Возвращает `False`, а не ошибку: это статус для админки (6.14c).

**R7. Жизненный цикл `httpx.AsyncClient`.**
Адаптер закрывает только собственный клиент; переданный извне — не
закрывает. `RuntimeLLMAdapter` использует refcount in-flight вызовов:
`invalidate()/aclose()` переносят адаптер в `_retired`, а закрытие
происходит после завершения активных `generate()`. В 6.14c DI должен
вызывать `aclose()` на shutdown.

**R8. Промпты и данные.**
Prompt не логируется. Для облака светофор проверяется до расшифровки
ключа. Тесты используют синтетические строки, не данные проектов.

**R9. Новых зависимостей нет.**
`httpx>=0.28` уже в `backend/pyproject.toml`. `respx` не добавляем:
используем `httpx.MockTransport`.

**R10. Загрузчики и сессии.**
`load_active_settings` / `load_api_key` / `load_project` в 6.14b —
абстрактные async-callable; в 6.14c DI оборачивает их в
`async with AsyncSessionLocal()`. Runtime не хранит сессию.
До 6.14c Runtime нельзя подключать к приложению без таких загрузчиков.

**R11. `updated_at` как часть ключа кэша.**
Если две правки настроек попадут в одну микроверсию `updated_at`,
кэш может не заметить вторую. Митигация: `invalidate()` из 6.14c при
каждой мутации; TTL 60s — верхняя граница.

**R12. Health fallback для шлюзов без `/models`.**
При 404/405 выполняется минимальный `POST /chat/completions`
(`max_tokens=1`), что расходует токены и требует ключ. Это только
health-check админки, не рабочий вызов.
