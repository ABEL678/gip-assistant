# docs/specs/ — спецификации вех

Спецификации вех дорожной карты 7.0. Каждая веха — своя спека.

## Зачем

- Рабочий документ на одну веху (5–10 страниц).
- Пишется перед началом вехи.
- GigaCode читает спеку → делает веху.
- Живёт 4 недели. Не устаревает.
- ТЗ 5.0 отменено в пользу спек по вехам (docs/specs/).

## Формат спеки (12 разделов)

1. Что делаем — одно предложение + ценность.
2. Сущности — домен, поля, связи.
3. Модель БД — SQLAlchemy + миграция.
4. DTO — Pydantic-схемы.
5. Порты и репозитории.
6. Сервисы.
7. DI и эндпоинты.
8. Тесты.
9. UI.
10. Открытые вопросы вехи.
11. Демо.
12. Что НЕ входит.

## Спеки

- `spec_week_1.md` — Система знает вводные и предлагает цели.
- `spec_week_2.md` — Система предлагает действия (планируется).
- `spec_week_3.md` — Система предлагает решения и связи (после вехи 2).
- `spec_week_4.md` — Система ведёт RFI (после вехи 3).
- `spec_week_5.md` — Система следит за сроками (планируется).
- `spec_week_6.md` — Пилот (планируется).

## Правила

- Одна веха — одна спека.
- Пишется перед началом вехи.
- Статус: `draft` → `active` → `done`.
- После завершения вехи — спека остаётся в `docs/specs/`, не
  архивируется (это история решений по вехе).
