## 1. Что это за продукт

**ГИП-Ассистент** — среда управления проектом для ГИПа (главного инженера
проекта). Не «удобный Excel» и не «красивый Проводник», а среда, где
структура проекта вырастает из вводных и логики управления.

**Формула ядра:**

    Управление проектом = Вводные предпосылки + Логика управления + Механизм вывода

- **Вводные** — договор, ТЗ, требования Заказчика, ИД, нормы, НПА, ресурсы.
- **Логика управления** — Goal / Decision / Task / Action.
- **Механизм вывода** — превращает вводные в структуру: система знает
  вводные и предлагает структуру, ГИП утверждает.

**Что даёт ГИПу:** связную картину проекта (что от чего зависит, что
блокирует), сохранение связей «письмо → запрос → том → срок», гибкую
структуру под ситуацию, делегирование рутины агентам.

**Топ-5 болей (12 интервью):** координация смежников (10/12), просрочки
(9/12), потеря задач (8/12), согласования (7/12), изменения/РВИ (6/12).

## 2. Ядро продукта

| Слой | Что | Где |
|------|-----|-----|
| **Вводные** | Внешняя образующая: договор, ТЗ, ИД, нормы, НПА, ресурсы | DOMAIN.md §3 |
| **Логика управления** | Goal → Decision → Task → Action. RFI — особый Task | DOMAIN.md §4 |
| **Структура управления** | Результат: вводные + логика на конкретном проекте | DOMAIN.md §5 |

**Дополнительно:** Document — полиморфная сущность (§7.1); Norm — внешний
норматив (§7.2); агенты — сотрудники с ролью (§9); LLM — механизм вывода
(§9.1).

**Ключевые свойства:**
1. Вводные и логика не статичны: вводные пополняются через RFI, логика перестраивается.
2. Структура — не модель, а результат; на разных проектах разная.
3. ГИП может работать на любом уровне — заполнять всё не требуется.
4. Движение двустороннее: сверху вниз (план) и снизу вверх (реакция на факт).
5. Агент предлагает — ГИП решает. Автономия только там, где делегировано.

## 3. Архитектура (кратко)

**Гексагональная:** domain / application / adapters. Домен не зависит от
FastAPI/SQLAlchemy.

- **Backend:** FastAPI + SQLAlchemy 2.0 async + Alembic.
- **Frontend:** React 18 + Vite + TS + shadcn/ui + TanStack Query + Axios.
- **Bot:** aiogram 3.x. **Storage:** MinIO AIStor Free. **LLM:** Qwen 2.5 7B локально.
- **Агенты:** слой поверх структуры, работают через Agent Gateway.

**Модель данных:** системные сущности (Project, Goal, Decision, Task, Action,
RFI, Document, DocumentVersion, DocumentLink, Norm, User, Executor,
ImportLog) + пользовательские (EntityType + Entity в JSONB).

Подробнее — `ARCHITECTURE.md`.

## 7. Ключевые принципы

1. **Домен чистый** (без FastAPI/SQLAlchemy).
2. **Порты и адаптеры** (гексагональная архитектура).
3. **Вводные + логика = структура управления проектом.**
4. **Структура не жёсткая** — вырастает из вводных, меняется под ситуацию.
5. **Система предлагает — ГИП утверждает.** Это не таск-трекер.
6. **XML — обязательное требование экспертизы.**
7. **AI-контекст — часть продукта.**
8. **ИИ-инструменты — только с поддержкой в РФ:** GigaCode (PyCharm).
9. **Один шаг за раз, с проверками.**
10. **Тесты для бизнес-логики обязательны.**
11. **Не коммитить в main напрямую.**
12. **Не менять `.env` и секреты.**
13. **UX — канвас, не списки.** ГИП думает связями.
14. **Абстракция валидатора:** `GoalValidatorService` — порт; реализации
    `RuleBasedGoalValidator` (вехи 1–5), `LLMGoalValidator` (веха 6).
15. **Агенты — в песочнице, через Gateway.** Без прямого доступа к БД/файлам;
    только Agent Gateway + `gip-mcp-gateway`. Сторонние MCP запрещены.
16. **LLM-настройки — в БД, ключи шифруются** (Fernet, `LLM_ENCRYPTION_KEY`).
    Светофор — по `Project.data_security_level`, не regex.

## 8. Что НЕ делать (антипаттерны)

- Не использовать Celery, Redis, RabbitMQ (MVP).
- Не использовать публичные облачные LLM.
- Не менять архитектуру без согласования.
- Не использовать `try/except` для валидации (Pydantic).
- Не добавлять зависимости без разрешения.
- Не смешивать правила кода (`RULES.md`) и правила текстов ПД.
- **Не строить продукт на описании постфактум** — проверять на сценариях.
- **Не навязывать структуру** — поддерживать все уровни, не требовать всё.
- **Не путать «документооборот» и «управление проектом».**
