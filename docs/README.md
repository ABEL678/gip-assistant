# docs/ — карта документации

> **Назначение:** единственная точка входа в документацию проекта.
> Здесь — что читать, в каком порядке и что можно менять без согласования.
>
> **Главный документ проекта — `context/DOMAIN.md`.** Онтология ядра.
> Если есть противоречие между документами — верен `DOMAIN.md`.

**Версия:** 1.0
**Обновлено:** 25.10.2026

---

## 0. Четыре уровня

| Уровень | Что | Можно менять |
|---------|-----|--------------|
| **1. Закон** | Онтология, правила кода, правила для ИИ | Только с согласования человека |
| **2. Спеки** | Стратегия, спеки вех, архитектура, БД, API | По мере работы над вехой |
| **3. Статус** | Что сделано, что в работе, эстафета | Обновляется после каждой задачи |
| **4. Рабочее** | Планы, шаблоны, промпты аудита | Свободно |

## 5. Порядок чтения

**ИИ-агент (обязательно):**
1. `../AGENTS.md` — правила.
2. `context/DOMAIN.md` — онтология.
3. `context/CONTEXT.md` — резюме продукта.
4. `context/TASKS.md` — статус.
5. `context/ARCHITECTURE.md` + `context/RULES.md`.
6. `DATABASE.md` / `API.md` — если задача их касается.

**Человек-разработчик:**
1. `context/CONTEXT.md` (~10 мин).
2. `context/ARCHITECTURE.md` (~15 мин).
3. `context/RULES.md` (~10 мин).
4. `context/DATABASE.md` и `context/API.md` (~20 мин).
5. `context/TASKS.md` — что делать.

**Вернулся через 2 недели:**
1. `context/HANDOFF.md` — где остановились.
2. `context/TASKS.md` §5 «Журнал» — что делали последним.
3. `context/CONTEXT.md` — напоминание о продукте.

## 6. Правила обновления

- **После каждой задачи:** обновить `TASKS.md` (статус + журнал) и, если менялась суть продукта, `CONTEXT.md`. Всё — в том же коммите, что и код.
- **Изменились эндпоинты** → `API.md`.
- **Изменились таблицы/поля** → `DATABASE.md`.
- **Новая веха** → спека в `specs/`, план в `tasks/`.
- **План закрыт** → перенести в `tasks/archive/`.
- **`HANDOFF.md`** — только по маркеру `[handoff]` или по прямой просьбе человека.
- **Уровень 1** (Закон) — только с согласования человека.

### Планы автоматизации (не реализовано)

В MVP-2 планируется автогенерация `DATABASE.md` (`sqlacodegen`), `API.md` (OpenAPI) и `RULES.md` (ruff) через GitHub Actions. До реализации файлы обновляются вручную.

## 7. Git

- **Коммитятся:** `docs/README.md`, `docs/context/**`, `docs/specs/**`, `docs/tasks/**`, `docs/templates/**`, `docs/tools/**`, `docs/Дорожная_карта_7.0.md`.
- **Не коммитятся:** бинарники (`.docx`, `.xlsx`), логи, секреты.
- **`docs/archive/` не ведётся.** Устаревшие документы остаются в git-истории. Для закрытых планов есть `tasks/archive/`.

Проверка:

    git check-ignore -v docs/README.md
    # пусто — файл коммитится

## 8. Чего здесь нет

- Секретов (`.env`, ключи, пароли).
- Больших бинарных документов (`.docx`, `.xlsx`).
- Логов и временных файлов.
- Дублирующих правил: правила для ИИ — только в `../AGENTS.md`.
