# docs/context/ — AI-контекст проекта

> **Назначение:** единый источник правды для ИИ-ассистентов,
> разработчиков и будущих участников проекта.

**Версия:** 1.0
**Обновлено:** 11.10.2026

---

## 1. Зачем это нужно

**Проблема:** каждый новый чат с ИИ и каждый новый разработчик начинает с нуля.

**Решение:** единая папка `docs/context/`, где собрана вся суть проекта.

**Для кого:**

- **GigaCode** (PyCharm-плагин) — использует как Project Context.
- **Самописный ИИ-агент** — читает перед началом работы.
- **Человек-разработчик** — для быстрого онбординга.
- **Ты сам** — при возвращении к проекту через месяц.

---

## 2. Состав

| Файл | Назначение | Обновление |
|------|-----------|------------|
| `CONTEXT.md` | Резюме проекта (2 страницы) | Вручную |
| `TASKS.md` | Что сделано / в работе / дальше | Вручную |
| `ARCHITECTURE.md` | Структура, слои, стек | Вручную |
| `DATABASE.md` | Схема БД (все таблицы) | Вручную (MVP-2: автогенерация) |
| `API.md` | Эндпоинты API | Вручную (MVP-2: автогенерация) |
| `RULES.md` | Правила кода | Вручную (MVP-2: автогенерация) |
| `README.md` | Этот файл | Вручную |

**Плюс в корне репозитория:** `AGENTS.md` — системный промпт для ИИ-агентов.

---

## 3. Как использовать

### 3.1. С ИИ (чат, GigaChat, другой)

**Сценарий 1. Новый чат**

Копируешь первые 2 страницы `CONTEXT.md` → вставляешь первым сообщением. ИИ сразу понимает проект.

**Сценарий 2. Работа с кодом**

Перед началом — даёшь ИИ:

- `CONTEXT.md` — что за продукт.
- `TASKS.md` — что в работе.
- `RULES.md` — как писать код.
- `ARCHITECTURE.md` — куда класть код.

### 3.2. С GigaCode (PyCharm)

1. Установить плагин GigaCode.
2. Settings → Tools → GigaCode → Project Context → добавить `docs/context/`.
3. Все запросы к ИИ учитывают актуальную документацию.

### 3.3. С самописным ИИ-агентом

Агент **автоматически** читает `docs/context/` перед началом работы. См. `AGENTS.md`.

### 3.4. Для человека

**Новый backend-разработчик:**

1. Читает `CONTEXT.md` — что за продукт (5 мин).
2. Читает `ARCHITECTURE.md` — как устроен код (15 мин).
3. Читает `DATABASE.md` — схема БД (10 мин).
4. Читает `API.md` — эндпоинты (10 мин).
5. Читает `RULES.md` — правила (10 мин).
6. Смотрит `TASKS.md` — что делать (5 мин).

**Итого:** ~1 час вместо 2 дней.

## 4. Что НЕ хранить здесь

- ❌ Секреты (`.env`, ключи).
- ❌ Большие документы (Дорожная карта, ТЗ — они в `docs/`, но не в `docs/context/`).
- ❌ Файлы других форматов (`.docx`, `.xlsx`).
- ❌ Логи (они в `docs/tasks/`).
- ❌ TODO-списки (они в `TASKS.md` или `backlog.md`).

**Только Markdown, только текст, только суть.**

## 5. Правила обновления

### 5.1. Что обновляется вручную

- `CONTEXT.md` — при стратегических изменениях.
- `TASKS.md` — перед новым чатом с ИИ, после крупной задачи.
- `ARCHITECTURE.md` — при архитектурных изменениях.
- `RULES.md` — при изменении правил кода.

### 5.2. Что обновляется автоматически (MVP-2)

Через GitHub Actions (`.github/workflows/sync-ai-context.yml`):

- `DATABASE.md` — из SQLAlchemy-моделей (`sqlacodegen`).
- `API.md` — из OpenAPI (`/openapi.json`).
- `RULES.md` — из `pyproject.toml` (ruff).

**Триггеры:**

- `DATABASE.md` — изменение `backend/src/adapters/db/models/**`.
- `API.md` — изменение `backend/src/adapters/api/routes/**`.
- `RULES.md` — изменение `pyproject.toml`.

### 5.3. Git

- **Все файлы `docs/context/` — коммитятся.**
- **Остальное `docs/`** — игнорируется (`.gitignore`).

**Проверка:**

    git check-ignore -v docs/context/CONTEXT.md
    # пусто (не игнорируется)

    git check-ignore -v docs/ТЗ_4.3.md
    # docs/* (игнорируется)

## 6. Порядок чтения (для ИИ-агентов)

**Обязательно:**

1. `CONTEXT.md` — что за продукт.
2. `TASKS.md` — статус, что в работе.
3. `ARCHITECTURE.md` — структура, слои.
4. `RULES.md` — правила кода.

**По необходимости:**

5. `DATABASE.md` — если работаешь с БД.
6. `API.md` — если работаешь с эндпоинтами.

**Плюс:** `AGENTS.md` (в корне) — системный промпт.

## 7. Сценарии

### 7.1. Ты вернулся к проекту через 2 недели

1. Открываешь `TASKS.md` — видишь, где остановился.
2. Открываешь `CONTEXT.md` — вспоминаешь продукт.
3. Читаешь «Журнал» в `TASKS.md` — что делал последним.
4. Продолжаешь.

### 7.2. Новый чат с ИИ

1. Копируешь `CONTEXT.md` + `TASKS.md` в начало чата.
2. Просишь ИИ: «Прочитай, потом начнём».
3. ИИ понимает контекст.
4. Работаете.

### 7.3. Новый разработчик

1. Клонирует репозиторий.
2. Открывает `docs/context/README.md` (этот файл).
3. Читает 6 файлов (~1 час).
4. Готов к работе.

### 7.4. GigaCode в PyCharm

1. Устанавливает плагин.
2. Настраивает Project Context → `docs/context/`.
3. Работает — ИИ видит актуальную документацию.

### 7.5. Самописный агент

1. Запускаешь: `python -m backend.scripts.ai_agent --task docs/tasks/my_task.md`.
2. Агент читает `docs/context/` + `AGENTS.md`.
3. Выполняет задачу.
4. Логи пишет в `docs/tasks/`.

## 8. Что дальше (MVP-2)

- **Test-writer** — генерация тестов.
- **Doc-keeper** — обновление документации.
- **Migration-checker** — проверка миграций Alembic.
